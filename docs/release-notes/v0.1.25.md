## Compute 0.1.25: the agent just works

0.1.23 and 0.1.24 put an agent panel on the Work page but left the agent to the
operator: export a target, a token file, a project and a model, then start
`compute-configured-stack-agent serve` by hand. That is not native.

- **Compute starts the agent itself.** On a configured install, the first goal
  for an environment starts the install's stack-agent service on loopback and
  supplies everything it needs: the computer host and credential from the pool,
  the environment's repository as the project, the worker from the install's
  profile, a free port and a per-project work database. The service starts from
  an empty environment. A service that dies as it starts is reported with its own
  last output.
- **One question, once: the model.** If the daemon has no `CHIP_*` settings, the
  panel asks for a provider, a model and an endpoint (and a key for a hosted
  model). It is saved in a file only the daemon's user can read and is never
  returned by the API. Changing it restarts the agent.
- **It works for a daemon started as plain `compute start`.** The configured
  install is found from the Homebrew layout, so the daemon need not be started
  through `compute-configured`.
- Running the service yourself still works: **Use a different agent service**
  registers its address and takes precedence.
