## Compute 0.1.23: the Work page can run and steer an agent

The Manage page's "Agent" template added `sh -c 'exec ./agent'`, a placeholder
for a file that exists nowhere, so the agent failed on every start. The agent
is stack-agent, a host service; it was never something a template could launch.

- **Agent panel on the Work page.** Give the agent a goal, watch its events,
  cancel it. The controller relays to the service the operator runs
  (`compute-configured-stack-agent serve`) through `GET /agent`,
  `POST /agent/work`, `GET /agent/work/{work}`, `…/events` and `…/cancel`.
  `COMPUTE_STACK_AGENT_URL` says where it listens (default
  `http://127.0.0.1:8765`; plain http loopback only). Nothing is stored and no
  Compute credential is forwarded. An unreachable service says so and how to
  start it. See docs/stack-agent.md.
- **The broken "Agent" template is gone.**
- **A project nothing runs now says so.** When Compute finds no start command
  (no `start` script, Procfile or Makefile `run`), the Work page shows the
  project has no URL and offers a Run form (command and port) that adds an
  application, which publishes an endpoint.
